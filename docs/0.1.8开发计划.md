# Matrix V0.1.8 开发计划

定位：0.1.7 之后的**工作流闸门硬化**版本，单一主题：把 design→build 的执行主体选择从 SKILL 提示词的软约束升级为 Runtime 状态机硬闸门，并清除 `auto_transition` 死配置。

- 分支：`codex/matrix0.1.8`（自 master `49ae2b4` 切出）
- 背景：用户实测发现 agent 可把总括授权（"按你推荐的做一版"）折叠为执行主体决策、静默推过 design→build；代码审查证实 0.1.6 F8 当时的取舍（"SKILL 指令层保证、Runtime 不阻断"）构成机制缺口——该决策点仅存在于 SKILL.md 文本，Runtime 无任何强制与记录，且 `auto_transition: true` 是 init 写入但全无读取点的装饰字段。
- 发布流程：沿用《0.1.5开发计划.md》第五节；发布前须用户确认（对外动作纪律）。

## 一、特性设计

### F1 — 执行主体闸门（EXECUTOR_CONFIRMATION_REQUIRED）

- `transition build`（full 与 lightweight 统一）新增必填参数 `--executor <current|model|handoff:<agent-id>>`：
  - `current`：当前 agent / 原模型继续；
  - `model`：用户客户端切换模型后继续；
  - `handoff:<agent-id>`：切换实现 agent（kebab-case，与 export `--agent` 同规则），衔接 `$matrix-handoff`。
- 缺失返回新错误码 `EXECUTOR_CONFIRMATION_REQUIRED`（message 要求先向用户呈现三选项；刻意不带 recovery_command，防止 agent 抄命令绕过询问）；非法值 INVALID_INTENT。
- lightweight 的 `--confirmed` 语义不变，确认顺序在前（缺 confirmed 时仍先报 CONFIRMATION_REQUIRED）；执行主体选择并入同一次暂停（与 0.1.6 F8 设计一致）。
- 选择写入 change 状态新字段 `implementation_actor`（matrix.yaml + transition 事件的 events.jsonl 审计），事后可验证"这步问过并记录了什么"。
- SKILL.md 双语同步：matrix-design 三选项各配对应 runtime 参数、主 SKILL 规则改为"传给 Runtime"表述、matrix-open 的 lightweight 命令补参数、README 双语命令示例补参数。

### F2 — 清除 auto_transition 死配置

- runtime init 与 distribution 的 `configContent` 均不再写 `auto_transition`；`configContent` 重写时显式丢弃旧字段（已装项目 update 后 config.yaml 自动净化）。
- Runtime 读取端本就只认 `installation_scope`/`default_orchestration`/`language`，旧 config 残留该字段无害（测试 fixture 保留旧格式以覆盖此兼容面）。

## 二、兼容性

- schema 保持 `matrix/change/v2`：`implementation_actor` 为可选新字段（normalizeFlow 经 `...flow` 透传；flowContent 对 falsy 不输出，旧 change 重写状态时不产生空行）。
- 已在 build/verify/archive 的旧 change：不再经过 `transition build`，零影响。
- 停在 design（full）或 open（lightweight）的旧 change：升级后首次推进被闸门拦截——这正是硬化目的；agent 收到错误码后向用户呈现三选项。
- 升级路径：SKILL.md 与 runtime 内容变化改变 matrix skill hash → 全平台 backup-replace；matt-catalog matrixVersion 0.1.7→0.1.8 参与 catalogDigest，已装项目首次 update 触发一次 Matt 重新核对（既有预期机制）。

## 四、验证

1. 全量测试（基线 137 + 新增 2：full 闸门四态〔缺失/非法/handoff 合法/状态与事件落盘〕、lightweight 双闸门顺序）。
2. 旧格式 config.yaml（含 auto_transition）在 runtime 与 distribution 下均正常（既有 fixture 覆盖）。
3. dogfooding：本仓库 change 走一次 design→build，验证闸门拦截与 `implementation_actor` 落盘（发布后）。

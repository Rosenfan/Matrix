# Matrix V0.1.6 开发计划

定位：0.1.5（链路修复）之后的**安装更新体验 + 工作流人机协作增强**版本。范围来自《0.2.0需求文档》顶部遗留的 init/update 改进笔记（F1–F3），以及用户 2026-09-19 追加的三个工作流协作需求（F7–F9）：Open 主动澄清、Build 前执行主体确认、通用 agent 交接。

- 分支：`codex/matrix0.1.6`（**自 v0.1.5 发布点切出**，前置依赖见下）
- 前置依赖：0.1.5 已完成 F5（skills 源位于 `assets/skills/`，`.claude/skills` 仅为安装目标）与 F6（EOL 归一化哈希口径）。本计划中所有 SKILL.md 路径均指 F5 迁移后的新源位置。
- 基线：v0.1.5 发布点，测试数以该点实测为准（0.1.4 基线为 116/116）
- 发布流程：沿用《0.1.5开发计划.md》第五节「版本路线」，此处不重复

## 一、当前架构理解（与本次范围相关）

**CLI 安装/更新侧（F1–F3）**：

- CLI 共三个命令：`init` / `update` / `doctor`，入口 `src/cli.js`。
- `init` 交互链：Language → Scope → Platforms → Matt → Default orchestration（`intentFrom`）。其中编排选择只显示裸标签 `Arch` / `Prim`，没有任何说明。
- 安装完成后的收尾输出为 `<Platform>: $matrix <request>`，未解释这条指令是什么、能做什么。
- `update` 继承 init 的安装设置，只做 self-update 检查 + 资产刷新；Matt 状态（`inspectMattInstallation`）仅在结束时展示一行，检测到不完整时**不会**询问用户。现有交互确认模式只有两个先例：Matrix 资产被用户改（`USER_MODIFIED_BLOCKED`）与 Matt 内容被改（`MATT_USER_MODIFIED`），均为「确认 → 带新策略重新 evaluate」。
- 全局安装在 `~/.matrix/`，项目安装在 `<project>/.matrix/`；**不存在任何"已安装项目"的索引**。
- `ui.select` 的选项为单行 label 渲染，不支持描述行。

**工作流侧（F7–F9 相关）**：

- Open 阶段（`matrix-open` SKILL.md）：Arch 模式下 grilling 是**条件触发**（"仅在存在重大歧义或用户要求压力测试时调用"），Prim 用自身能力澄清；没有强制的澄清产物文件，澄清内容直接进 proposal。
- Design→Build 边界：`transition build` 在 design guard 通过后直接推进；主 SKILL.md 的暂停确认规则只覆盖"重大架构/范围决定和 archive/commit"，不含执行主体选择。
- agent 交接（`matrix-claude` SKILL.md）：硬编码"Codex 设计、Claude Code 实现"——`export --target generic` 产出 `claude-task.md`，任务包元数据写死 `Decision owner: Codex` / `Implementation actor: Claude Code`；lightweight 工作流不支持导出。
- CONTEXT.md 已有通用术语 **Implementation handoff**（"已批准 Contract 向其他实现执行者的可选导出；不拥有阶段推进或验收"），泛化在术语层有现成依托。
- 产物策略（`ARTIFACT_POLICY`）校验固定标题 token；`matrix-claude` 引用面集中在 `catalog.js` MATRIX_SKILLS、`package.json` files、`test/package.test.js` 三处。
- distribution 观测只遍历当前 `MATRIX_SKILLS`；清单中移除的 skill 目录升级后不会被自动删除，保留为未纳管目录（安全降级，已有 unmanaged 诊断机制）。

## 二、需求与差距

| 需求 | 现状 | 差距 |
|---|---|---|
| init 两个编排加中英文注释；收尾说明功能是什么 | 裸标签；`$matrix <request>` 无解释 | F1 |
| update 检测 Matt skills 不完整时确认是否拉取 | 仅展示状态，无确认流程 | F2 |
| update 增加 Update scope（全部已索引项目 / 仅当前项目） | 无项目索引，无法迭代 | F3 |
| Open 阶段主动澄清需求（默认调用 grilling；用户明确豁免时仍落澄清文件） | grilling 条件触发，无强制澄清产物 | F7 |
| Build 前暂停确认执行主体（换模型 / 原模型继续 / 换 agent） | design→build 直接推进，无确认点 | F8 |
| 跨 agent 交接通用化（任意"设计 agent → 执行 agent"，不限定 Codex/Claude Code） | matrix-claude 硬编码双角色 | F9 |

## 三、特性设计

### F1 — init 编排说明与结果输出可理解性

- 编排选择项增加双语描述（中文安装显示中文、英文安装显示英文）：
  - **Arch**：编排项目内已安装的 Matt Skills 集合（需先安装 Matt）／ Orchestrates the installed Matt Skills cohort (requires Matt Skills).
  - **Prim**：仅使用 Matrix 自带能力，不依赖 Matt Skills ／ Uses Matrix's own capabilities only (no Matt dependency).
- `ui.select` 扩展：选项支持可选 `detail` 字段，渲染为 label 下一行的 dim 文本，方向键清除行数相应适配；无 `detail` 时渲染不变（向后兼容）。
- 收尾输出：在 `$matrix <request>` 前增加一句说明，例如「在 <平台> 中输入 `$matrix` 加你的请求，即可启动证据驱动工作流」，按安装语言输出。

### F2 — update 的 Matt 修复确认

- `update` 进入 `refresh` 前检测 `inspectMattInstallation` 状态 ∈ {`incomplete`, `update-required`, `unverified`} 时（交互模式且未 `--yes`）：
  - 询问「Matt Skills <状态>，是否重新拉取受支持的 release（v1.2.3）？」；
  - 确认 → 按现有 `MATT_USER_MODIFIED` 同款模式，以补装意图重新 evaluate 并执行修复（沿用 备份 → staging → Hash 校验 → 替换 的既有链路，不新增安装路径）；
  - 拒绝 → 仅跳过修复，其余资产照常刷新。
- 非交互（`--yes` / `--json`）行为不变：只输出诊断与建议命令，不修改 Matt。

### F3 — update 更新范围（项目索引）

- 新增全局项目索引 `<home>/.matrix/projects.json`：数组，元素 `{ path, scope, platforms, language, updatedAt }`；原子写（tmp + rename）；损坏时降级为「仅当前项目」并告警，不阻塞。
- `init` / `update` 成功 commit 后登记项目根（按路径去重）；该登记由 CLI 层调用独立索引模块完成，不侵入 `distribution.js` 的计划/提交逻辑。
- `matrix update` 交互新增询问 **Update scope**：`Current project only`（默认）/ `All indexed projects`；新增旗标 `--all` 与 `--project-only`，非交互默认 current project。
- `All indexed projects`：self-update 仅在首轮做一次，随后逐项目执行现有 update 流程（每项目 `--skip-self-update`）；逐项目隔离，单项失败不中断其余；目录已不存在的项目从索引移除并在汇总中报告；最终存在失败则整体以非零码退出。

### F7 — Open 阶段主动澄清

核心变更：澄清从「条件触发的例外」改为「Open 阶段的默认行为」，且无论是否豁免都产生澄清产物文件。

- **默认主动澄清**：
  - **Arch**：Open 开始即说明能力与原因并调用 `grilling`（触发条件从"存在重大歧义或用户要求"改为"默认启动"）；
  - **Prim**：用 Matrix 自身能力进行结构化澄清（目标、范围、非目标、验收标准、风险、时限），不依赖 grilling。
- **豁免条件（两个条件同时满足才可跳过澄清过程）**：
  1. 用户自带清晰的执行计划；
  2. 用户明确说明不需要澄清过程。
- **澄清产物（强制落盘）**：`<change>/clarification.md`，无论澄清或豁免都必须生成：
  - 正常澄清：`## Questions` / `## Answers` / `## Resolved scope`（英文标题 token 固定，正文按 `artifact_language`）；
  - 豁免路径：`## Exemption record`（豁免原因 + 用户计划要点 + 提案如何采纳该计划）。
- **边界约束**：
  - clarification.md 是 Open 阶段的**证据类产物**，不参与 Contract identity 计算（proposal 仍是唯一 contract 输入）——保证 contract hash 与既有 guard 行为零变化。
  - Runtime **不加阻断校验**（不检查 clarification.md 存在才允许 transition）：兼容 0.1.5 及更早创建、仍停在 open 阶段的 change 在 0.1.6 runtime 下正常推进。产物生成由 SKILL.md 指令保证。
  - lightweight（hotfix/tweak）同样适用主动澄清，但为精简版（一轮核心问题即可）；豁免规则相同。
  - Arch 触发策略是 release 级指引（cohort **身份**由 `arch_catalog_digest` 冻结，触发条件随 SKILL.md 发布）；0.1.6 将 open 的 grilling 默认化属于有意的 release 决策，不影响既有 change 的 cohort 身份，需在发布说明中明示。

### F8 — Design→Build 执行主体确认点

动机：设计阶段用能力更强的模型、执行阶段用性价比高的模型或另一 agent。模型/agent 的实际切换发生在用户客户端，Matrix 负责提供**强制决策点**与后续路径。

- `matrix-design` SKILL.md：`guard design` 通过后、`transition build` 之前，必须暂停向用户呈现三个选项，未确认不得推进：
  - (a) **当前 agent / 原模型继续**——直接 `transition build`；
  - (b) **切换模型后继续**——用户在自己客户端完成模型切换，回到会话确认后推进（Matrix 无法感知客户端模型，仅提供暂停点）；
  - (c) **切换执行 agent**——进入 F9 通用 handoff，导出任务包给目标 agent。
- 决策记录（不新增标题 token、不改 `ARTIFACT_POLICY`）：
  - full：执行主体决策写入 design.md 的 `## Decisions`（随 Contract 冻结）；
  - lightweight：写入 proposal 的 `## Approach` 正文（open→build `--confirmed` 的既有确认点与执行主体选择**合并为一次暂停**，不重复打断）。
- 主 `matrix` SKILL.md 规则区补充该确认点；Runtime 不加阻断（兼容红线同 F7）。

### F9 — 通用 Implementation handoff（matrix-claude 泛化）

将硬编码"Codex → Claude Code"的旁路泛化为任意"设计 agent → 执行 agent"的 Contract 导出，术语沿用 CONTEXT.md 的 **Implementation handoff**。

- **Skill 改名**：`matrix-claude` → `matrix-handoff`（`assets/skills/` 与 `assets/skills-zh-CN/` 双语源目录同步重命名、内容重写）：
  - 元数据示例改为通用形态，含 Codex→Claude Code、zcode→opencode 等示例；
  - 保留既有边界：仅在已批准 Contract 的 Build 阶段使用；不执行 transition/archive；仅支持 full/legacy-full 三产物 Contract。
- **export 命令参数化**（`src/workflow.js`）：
  - 新增 `--agent <agent-id>`（kebab-case 校验，目标执行者）：
    - 产物命名通用化：`<change>/handoff-task-<task-id>.md` 与 `handoff-result-<task-id>.md`（按 task-id 隔离，可多次导出）；
    - 任务包元数据参数化：`Implementation actor = <agent-id>`；`Decision owner` 由可选 `--from <agent-id>` 提供，缺省为通用表述 "Matrix change owner"；
    - Objective/Allowed/Prohibited/Stop-and-report 边界文本保持不变（这些与具体 agent 无关）。
  - **兼容保留**：`--target generic`（产出 `claude-task.md` 旧行为）与 `--target fnsec` 不删除、不改行为；旧测试断言不动，新增 `--agent` 路径测试。0.1.6 发布说明中标注 `--target generic` 为兼容形态、推荐 `--agent`。
- **主 `matrix` SKILL.md**：「可选 Claude 交接」节改写为「可选 agent 交接（Implementation handoff）」，引用 `$matrix-handoff`；与 F8 的选项 (c) 衔接。
- **清单同步**：`catalog.js` MATRIX_SKILLS、`package.json` files 增 matrix-handoff 删 matrix-claude；`test/package.test.js` 包结构断言随之更新（属发布内容演进，非行为回归）。
- **升级路径**：0.1.5 项目 `matrix update` 到 0.1.6 后，旧 `matrix-claude` 目录不在新清单中，distribution 不自动删除，保留为未纳管目录（沿用既有 unmanaged 安全降级语义）；发布说明指引手动清理，不在 0.1.6 引入清单收缩清理机制（避免新增删除类风险）。

## 五、风险分析

- **F3 引入全局写状态**：位置固定、原子写、损坏降级；对 npm 打包清单无影响（索引模块在 `files` 白名单内，pack:check 验证）。
- **文案改动影响既有测试断言**：F1/F2 预计小范围更新 messages/cli 测试，属预期内。
- **多项目迭代放大单项目故障**：逐项目 try/catch 隔离 + 汇总退出码；每项目的事务恢复语义沿用现有 `transactionPending`，互不穿透。
- **交互路径增多**：所有新增询问均有非交互等价旗标，`--json` 输出结构只增不改。
- **F7 行为语义变化**：grilling 在 Arch open 从条件触发改为默认主动，属 release 级指引变更；cohort 身份（digest）不变，既有 change 不受影响，但用户的交互节奏会变多——豁免规则必须写清楚，发布说明明示。
- **F7/F8 均为 SKILL 指令层保证、Runtime 不阻断**：产物与确认点的强制性依赖 SKILL.md 指令遵循度；换取零兼容破坏（既有活跃 change 完全可恢复推进）。若后续需要硬保证，可在 0.2.0 以新 schema 版本引入。
- **F9 改名升级残留**：旧 matrix-claude 目录升级后保留为未纳管目录，不自动删除（安全降级）；发布说明指引清理。清单收缩清理机制留待后续版本评估。
- **F9 export 兼容面**：`--target generic|fnsec` 原样保留，旧断言不动；`--agent` 为纯新增路径。

## 六、验证方式

1. 基线：0.1.5 发布点测试全绿；新增测试全部通过。
2. F1：en / zh-CN 各跑一次 init 交互冒烟，确认编排选项带描述、收尾含说明；无 TTY 场景渲染不回归。
3. F2：构造 Matt incomplete 的项目跑 `matrix update`，确认询问→修复→状态转 compatible；`--json` 与 `--yes` 行为与 0.1.5 一致。
4. F3：登记两个项目后 `--all` 迭代刷新；删除其中一个目录再跑 `--all`，确认自动清理并报告；损坏的 `projects.json` 降级不崩溃。
5. F7：prim 与 arch 各走一次 open，确认默认澄清、clarification.md 落盘；用户明确豁免时仍生成 `## Exemption record`；0.1.5 停在 open 的 change 在 0.1.6 runtime 下正常 transition（兼容冒烟）；contract hash 计算不受 clarification.md 影响。
6. F8：full 流程 design→build 前出现三选项确认；选 (a) 直接推进，选 (c) 进入 handoff；lightweight 一次暂停同时完成范围确认与执行主体选择。
7. F9：`export --agent opencode --task-id <id>` 产出 `handoff-task-<id>.md`，元数据 actor 正确；`--target generic` 旧行为回归通过；matrix-handoff 双语资产安装完整；0.1.5→0.1.6 update 后旧 matrix-claude 目录按设计保留不报错。
8. 收尾：全部测试全绿；`npm run pack:check` 打包清单无泄漏；发布 `release: v0.1.6`。

# Decouple the auto workflow from Matt Skills and keep the classic contract frozen

Matrix 0.2.0 introduces the `auto` workflow (`understand → execute → verify → close`) and makes it the default for newly initialized projects. `auto` does not depend on Matt Skills: a new `auto` installation installs only the `matrix` and `matrix-status` Skills, `matrix init` does not require Matt Skills (`--with-mattpocock` remains optional), no Matt content identity is checked or enforced during a Run, and the Agent may use any Skill the host already provides. This ADR partially supersedes ADR-0003 and ADR-0004: it replaces their premise that each Matrix release binds the whole product to one reviewed Matt release. Everything those ADRs say about `matrix/change/v2` changes under `arch` stays in force unchanged.

The part of Matt Skills that Matrix relied on is kept as text, not as a dependency. Five practices — deep modules with the interface as the test boundary, vertical slices that avoid self-proving tests, Standards and Spec reviewed as separate axes, YAGNI scope converged on `git log` hot spots, and investigating facts before asking — are distilled into `references/engineering-craft.md`, shipped inside the `matrix` Skill in English and Chinese with an MIT attribution to upstream commit `24fe0ef` (v1.3.1).

`classic` is the previous default and does not change. It keeps the five `matrix/change/v2` phases, the `prim` and `arch` orchestration modes, and the Matt compatibility contract exactly as ADR-0003 and ADR-0004 define it: `arch` is bound to the 27 reviewed official roles of Matt Skills v1.3.1, installs the 25 compatible Skills as content-verified project-local copies, excludes `implement` and `implement-spec`, and treats `matrix init --with-mattpocock` as the canonical Matt write path. In-flight `arch` changes keep their frozen cohort, hashes, and evidence, and upgrading Matrix does not rewrite them. Existing projects resolve to `classic` until the user opts in with `matrix init --default-workflow auto`.

For `auto` projects this makes Matt Skills the user's own dependency, with two boundaries:

- Users may install, upgrade, or remove Matt Skills with the skills CLI without waiting for a Matrix release. `matrix skills audit <path-or-name>` reports an external Skill's conflict risk through a read-only static scan; it runs none of the Skill's scripts, and the workflow itself never installs a Skill unattended.
- A freely upgraded Matt installation and an in-flight `arch` change are mutually exclusive, because `arch` requires all 27 content identities to equal v1.3.1. Such a change fails its integrity check until `matrix init --with-mattpocock` restores v1.3.1; users who want both must finish or abort the `arch` change first, or keep that work in a separate checkout.

`matrix update` is read-only toward Matt Skills in every workflow: it refreshes Matrix assets and reports Matt compatibility, never follows upstream to a newer release, never rewrites or removes a Matt Skill on its own, and never changes `default_workflow`. In an `auto` project it skips the Matt repair prompt; in a `classic` project it keeps offering the v1.3.1 repair.

Consequences: one entrypoint (`$matrix`) routes to two workflows, selected by `default_workflow` in `.matrix/config.yaml`. `orchestration.default` remains `prim` or `arch` and applies to `classic` only, so workflow and orchestration are stored as separate dimensions and the release catalog digest is computed from all ten Matrix Skills regardless of what a project installed. The Skill set each platform actually received is recorded in `installation.json`, so `matrix update` and `matrix doctor` keep an `auto` project at two Skills instead of repairing it back to ten. Reproducibility and the two-trust-domain supply-chain posture of ADR-0003 survive where they were designed to apply (`classic` with `arch`), while `auto` trades the pinned cohort for Runtime-executed checks and honestly declared review sources. Distilled guidance can drift from upstream; it records the commit it derives from and changes only through an ordinary reviewed Matrix change.

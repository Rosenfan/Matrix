# Matrix V0.1.7 开发计划

定位：0.1.6（安装更新体验 + 工作流协作）之后的**Matt 兼容合同升级 + 平台扩展**版本。范围来自两部分：上游 Matt Skills v1.2.3 → v1.3.1 的 reviewed patch（ADR-0003 规定的版本绑定变更程序），以及用户 2026-10-24 提出的新增平台需求（zcode、deepseek 等主流 agent）。

- 分支：`codex/matrix0.1.7`（自 master `6ecee0b` 切出，即 v0.1.6 发布点后的 docs 收尾提交）
- 基线：0.1.6 发布后测试 133/133
- 发布流程：沿用《0.1.5开发计划.md》第五节「版本路线」，此处不重复

## 一、当前架构理解（与本次范围相关）

**上游 v1.3.1 事实（2026-10-04 发布，commit `24fe0ef7737efae15c87225755e9f6f5965e4888`）**：

- 官方角色 **27 项** = `skills/engineering`（20）+ `skills/productivity`（7）：v1.2.3 的 25 项 − `resolving-merge-conflicts`（上游移除，无替代）+ `implement-spec` / `pr` / `retro`（三项毕业入 Engineering bucket，随 Claude Code plugin 分发并被 ask-matt 路由）。`misc` / `in-progress` / `deprecated` 桶不属于官方角色（与 v1.2.3 的 25 项口径一致，已逐桶核对）。
- 域文档约定改名：`CONTEXT.md`/`CONTEXT-MAP.md` → `GLOSSARY.md`/`GLOSSARY-MAP.md`，上游 skill 后续只认新名。
- 全仓库 em-dash 移除、六项 skill 的 YAML frontmatter 修复等 patch 级变化意味着**全部 27 项内容 hash 都会变化**。

**skills CLI（vercel-labs/skills，独立于 mattpocock/skills 内容仓库）**：

- npm 包 `skills` 最新版 **1.7.4**（Matrix 现 pin `1.5.22`）。
- 1.7.4 支持 `zcode` agent（项目级 `.zcode/skills/`，全局 `~/.zcode/skills/`——与本机 `~/.zcode/skills` 实证吻合）；**不认识 deepseek / deepcode**。
- DeepSeek 的 Deep Code CLI（`lessweb/deepcode-cli`）项目级约定 `.deepcode/skills/`、全局 `~/.agents/skills/`，支持 Agent Skills 标准（SKILL.md 目录格式）。

**Matrix 侧现状**：

- `src/matt-catalog.mjs` 是兼容合同唯一权威：`MATT_COMPATIBILITY`（matrixVersion/release/commit/archive/skillsCli）+ `MATT_ROLES` 四组 + `MATT_CONTENT_HASHES` 25 项 + `MATT_CATALOG_DIGEST`（四者全部参与 digest，任何变更都会触发已装项目的 Matt update-required → `matrix update --with-mattpocock` 修复链，机制 0.1.6 F2 已验）。
- 平台枚举权威在 `src/catalog.js` 的 `PLATFORM_IDS`/`PLATFORMS`（每条目：id/name/skillsCliAgent/skillRoot/legacyRoots）；但存在三处**硬编码旁路**：`src/workflow.js:254`（archIntegrity 的 `platform === "codex" ? ".agents" : ".claude"` 三元，未知平台静默落 `.claude`）、`src/workflow.js:388`（managedReviewPrefixes 同款三元，未知平台返回 null → review 托管前缀失效）、`src/runtime-resolver.js:31`（硬编码 `["codex","claude-code"]` 循环）、`src/installer.js:28`（`.agents` 子串嗅探）。CLI 层另有 `src/cli.js` HELP 与平台多选、`src/messages.js` `noPlatform` 双语文案。
- `workflow.js`（bundled 为 `matrix-runtime.mjs`）**不 import catalog.js**——分发时仅注入 workflow/transaction/matt-catalog 三个文件，runtime 必须自包含，平台映射无法直接复用 `PLATFORMS` 表。
- `matt.js` `prepareCandidate`：每平台跑 `npx skills@<pin> add <archive> --yes --copy --agent <skillsCliAgent> --skill <逐项>` 于临时目录，`verifyCandidate` 按 `PLATFORMS[platform].skillRoot(root)` 校验取件；distribution.commit 从候选目录拷贝到目标（`fs.cpSync`），全程事务化。
- 仓库根 `CONTEXT.md` 是 Matrix 自身域文档（GLOSSARY 术语表）；上游改名后，本仓库 dogfooding 安装的 Matt skills（domain-modeling、improve-codebase-architecture 等）将只识别 `GLOSSARY.md`。
- 工作流侧无版本耦合：`LEGACY_ARCH_SKILLS`（含 resolving-merge-conflicts）是 0.1.4 前 change 的历史兼容读取层，不依赖新 catalog。

## 三、特性设计

### F1 — Matt 兼容合同 v1.2.3 → v1.3.1

- `MATT_COMPATIBILITY`：matrixVersion `0.1.7`、release `v1.3.1`、commit `24fe0ef7737efae15c87225755e9f6f5965e4888`、archive 换对应 tar.gz、skillsCli `skills@1.7.4`（zcode agent 必需的最低升级）。
- `MATT_ROLES` 重组（官方 27 / 安装 25，用户已确认）：
  - automatic 十项不变（grilling、domain-modeling、research、prototype、codebase-design、tdd、diagnosing-bugs、code-review、wizard、writing-for-agents）；
  - handoff 增加 `retro`（6 项）——user-invoked、改进 agent 环境而非代码，与 improve-codebase-architecture 同类显式交接；
  - standalone 增加 `pr`（9 项）——model-invoked、只产出 PR 文本不触碰工作流状态，与 code-review 同类；
  - incompatible 改为 `["implement", "implement-spec"]`——两者都拥有实现过程（多 worktree 并行 spec 执行 / 单 ticket 实现），与 Matrix build 阶段治理冲突，排除理由同源；`resolving-merge-conflicts` 随上游移出清单。
- `MATT_CONTENT_HASHES` 27 项全部重算：临时目录 `npx skills@1.7.4 add <v1.3.1 archive> --yes --copy --agent codex --skill <27 项逐个>`，以仓库 `hashDirectory`（EOL 归一化）逐目录计算；注释同步 "produced by skills@1.7.4"。
- 文案（双语同步）：
  - `assets/skills{,-zh-CN}/matrix/SKILL.md`：Arch 段 "Matrix 0.1.4 reviews all 25 official Matt Skills v1.2.3 roles and installs only the 23 compatible Skills" → "Matrix 0.1.7 reviews all 27 official Matt Skills v1.3.1 roles and installs only the 25 compatible Skills"；排除项表述 `implement` and `implement-spec`；「显式 Matt handoff」节 handoff 列表加 `retro`（会话复盘）、standalone 名单加 `pr`、不安装管理项改为 `implement` 与 `implement-spec`。
  - `assets/skills{,-zh-CN}/matrix-build/SKILL.md`：保留 resolving-merge-conflicts 防御句（旧项目副本仍可能存在），追加 implement-spec 同类排除（拥有实现过程、越出 Matrix 生命周期治理）。
  - README 双语：版本绑定段（25/23/v1.2.3/commit）、Integration 章节、Matt 交互确认文案中的 release 号。
- 新增 `docs/adr/0004-matt-compatibility-contract-v1.3.1.md`：记录 27/25 新合同、三项新角色的评审结论（pr/retro 引入、implement-spec 排除的理由）、skillsCli 1.7.4 升级与 GLOSSARY 改名事实；supersede ADR-0003 的版本绑定，0003 原文不改。
- 测试：`test/matt-catalog.test.js`（新 MATT_COMPATIBILITY 值、四组名单 deepEqual、官方 27/安装 25 计数）；`test/distribution.test.js` 顶部计数断言（25 项 installable、十项 automatic、不含 implement/implement-spec）。
- `LEGACY_ARCH_SKILLS` 与 legacy 读取路径**不动**（历史 change 兼容层）。

### F2 — 平台映射表驱动化（加平台的前置重构）

- `src/workflow.js`：顶部新增内联 `PLATFORM_SKILL_ROOTS` 常量（platform id → 相对 skill 目录，四平台）；`archIntegrity`（254 行）与 `managedReviewPrefixes`（388 行）改查表，消除"未知平台静默落 `.claude` / 返回 null"。runtime 自包含所迫的双份定义，用**对拍测试**钉死：断言 workflow.js 内联表与 catalog.js `PLATFORMS` 的 skillRoot 相对路径一致，防漂移。
- `src/installer.js:28`：`.agents` 子串嗅探 → 反查 `PLATFORMS`（destination 反解 platform id）。
- `src/runtime-resolver.js:31`：硬编码数组 → `PLATFORM_IDS` 顺序迭代（保持 codex、claude-code 现有优先序，新平台随后）。
- `src/cli.js`：HELP `--platform` 枚举与交互多选选项由 `PLATFORM_IDS`/`PLATFORMS` 驱动生成（`{ label: name, value: id }`）。
- `src/messages.js`：`noPlatform` 双语文案覆盖四平台。
- 同步测试（cli HELP 断言、messages、workflow 对拍）。

### F3 — 新增 zcode 平台

- `src/catalog.js`：`PLATFORM_IDS` 加 `zcode`；`PLATFORMS` 加条目 `{ id, name: "ZCode", skillsCliAgent: "zcode", skillRoot: <base>/.zcode/skills, legacyRoots: [] }`。
- skills CLI 1.7.4 原生支持该 agent 与目录，prepareCandidate/verifyCandidate 现有逻辑零适配。
- 测试：catalog 平台条目、cli `--platform zcode` 解析、distribution zcode 安装观察（Matt 侧 mock adapter）。

### F4 — 新增 deepseek（Deep Code）平台 + Matt 布局映射

- `src/catalog.js`：`PLATFORM_IDS` 加 `deepseek`；`PLATFORMS` 加条目 `{ id, name: "DeepSeek (Deep Code)", skillsCliAgent: "codex", skillRoot: <base>/.deepcode/skills, legacyRoots: [], candidateLayout: ".agents/skills" }`——`candidateLayout` 为新增可选字段，表示 skills CLI 实际产出布局（缺省等于 skillRoot 自身布局，既有两平台不填）。
- `src/matt.js` `prepareCandidate`：每平台跑完 skills CLI 后，若 `candidateLayout` 存在且与 skillRoot 布局不同，将 `root/<candidateLayout>` 重命名到 `root/<skillRoot 布局>`（`fs.renameSync`）；`verifyCandidate` 按 `PLATFORMS[platform].skillRoot(root)` 校验（重映射后自然正确，现有代码不动）。
- 已知限制（README 与本计划明示）：
  - global scope 下 Deep Code 读 `~/.agents/skills`（与 codex global 同路径，两平台会重叠），0.1.7 的 deepseek **仅保证 project scope**；
  - Deep Code 属按其公开约定支持，未经实机验证，依靠 candidate hash 校验与事务回滚兜底。
- 测试：`matt.test.js` 布局重映射单测（mock run + 真实临时目录结构）、catalog 条目、cli 解析。

### F5 — GLOSSARY 改名与文档同步

- `git mv CONTEXT.md GLOSSARY.md`（仓库根域文档；dogfooding 安装 v1.3.1 后上游 skill 只认新名）。
- 本版新写文档（本计划、ADR-0004）一律用 GLOSSARY.md 术语；《0.1.5开发计划.md》《0.1.6开发计划.md》为历史文档不改；assets 源目录无 CONTEXT 引用（已验证）；`.agents/skills` 本地旧副本随 `update --with-mattpocock` 刷新为新版（新版自带 GLOSSARY 约定）。

### F6 — 顺手修（小项）

- 0.1.7 待办①：`src/cli.js` `refresh()` 的两个 `--json` inspect 调用透传 update 版 `action`（非 JSON 路径与 doctor 已正确）。

## 五、风险分析

- **skills CLI 1.5.22 → 1.7.4 行为变化**（参数语义/TUI/产物布局）：本版唯一可能扩大改动面的点。缓解：实施第一步先以 codex 布局完整冒烟（27 项 --skill），确认参数与产物结构后再写 hash 表；无 TTY 行为一并观测（待办②）。
- **hash 表与 CLI 版本耦合**：表注释与 pin 同步 1.7.4；冒烟确认 `--copy` 产物结构（SKILL.md + 附带文件集合）与 1.5.22 一致，若产物含版本相关差异需在 verifyCandidate 层评估。
- **升级路径**：0.1.6 项目 catalogDigest 变化 → Matrix skills outdated（backup-replace）+ Matt update-required → `matrix update --with-mattpocock` 一次完成；matrix SKILL.md 文案变化改变 matrix skill hash 属正常替换路径。
- **deepseek 布局映射**：`renameSync` 失败（如 skills CLI 产出与预期不符）会走 `MATT_INSTALL_FAILED` 清理路径，不污染目标项目；`.deepcode` 布局未经 Deep Code 实机验证，README 标注。
- **zcode 与 codex 全局目录**：zcode global（`~/.zcode/skills`）与 codex global（`~/.agents/skills`）不同目录，无重叠；deepseek global 的重叠已在 F4 已知限制中声明。
- **测试基线**：matt-catalog/distribution 的计数断言与 MATT_COMPATIBILITY deepEqual 属预期更新；新增对拍测试把 workflow 内联表与 catalog 表锁死。

## 六、验证方式

1. 冒烟（F1 前置）：`npx skills@1.7.4 add <v1.3.1 archive> --yes --copy --agent codex --skill <27 项>` 于临时目录成功、27 个 skill 目录齐备、hash 表产出；同命令 `--agent zcode` 验证 `.zcode/skills` 布局。
2. 单测：`node --test` 全绿（基线 133 + 新增：27/25 计数与名单、四平台表、workflow↔catalog 对拍、deepseek 重映射、`--platform zcode|deepseek` 解析）。
3. 集成：packed-install 测试扩展 zcode 平台（mock Matt adapter）；`npm run pack:check`。
4. dogfooding（用户交互终端）：`matrix update --with-mattpocock --platform codex --platform zcode`，验 zcode 会话可见 25 项 Matt skills 与 10 项 matrix skills；deepseek 验安装产物路径与 hash，实机留待用户。
5. 发布后：`npm view` / `gh release` / 全局 CLI 升级 / doctor 双源。

## 八、发布前修订（2026-10-25，用户评审反馈）

- **移除 deepseek 平台条目**（含 `candidateLayout` 布局映射机制与对应测试）。理由：平台条目只应面向存在真实 agent CLI 工具的目标；DeepSeek 无官方 agent 工具，Deep Code 属第三方且未实机验证，不应内置。
- **平台策略口径**：Matrix 只为拥有独立 skill 目录约定的 agent 内置平台条目（Claude Code `.claude/skills`、Codex `.agents/skills`、ZCode `.zcode/skills`）；默认读取 Agent Skills 开放标准 `.agents/skills` 目录的工具（opencode、Kimi Code 等兼容 agent）共享 Codex 平台的安装产物，无需单独平台条目，README 双语已明示。
- F2 表驱动化、F1 合同、F5、F6 维持不变；版本仍为 0.1.7（npm 未发布，GitHub tag 与 Release 待用户确认后更新）。
